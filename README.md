# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.


### Данные
В приложении используются две сущности, которые описывают данные, — товар и покупатель.  Их можно описать такими интерфейсами:
Интерфейс IProduct описывает состав продукта (товара) в интернет-магазине. Его поля:

`id: string;` - уникальный идентификатор товара.
`description: string;` - описание товара.
`image: string;` - путь к изображению товара.
`title: string;` - название товара.
`category: string;` -  категория товара.
`price: number | null;` - цена товара. Значение null означает, что товар "Бесценно" и не может быть добавлен в корзину.

Интерфейс IBuyer описывает данные покупателя, необходимые для оформления заказа. Его поля:

`payment: TPayment;` - способ оплаты (карта, наличные или не выбран).
`email: string;` -  электронная почта покупателя.
`phone: string;` - номер телефона покупателя.
`address: string;` - адрес доставки.

### Модели данных
Для учёта данных в приложении используются три класса, которые разделены между собой по смыслу и зонам ответственности:
CatalogModel — хранение товаров, которые можно купить в приложении;
CartModel — хранение товаров, которые пользователь выбрал для покупки;
OrderModel — данные покупателя, которые тот должен указать при оформлении заказа.

#### Класс CatalogModel 
Управляет каталогом товаров, доступных в магазине. Отвечает за хранение всех товаров и выбранного для детального просмотра товара.

Конструктор:
`constructor(events:EventEmitter) { this.events = events;}` - В конструктор передается экземпляр брокера событий EventEmitter, который используется для генерации событий при изменении данных в модели.
Поля класса:
`_products: IProduct[]` -  массив всех товаров, полученных с сервера.
`_selectedProduct: IProduct | null` - товар, выбранный пользователем для подробного просмотра.
`events: EventEmitter` - брокер событий для уведомления об изменениях.

Методы:
`setProducts(products: IProduct[]): void` - сохранение массива товаров, полученного в параметре метода. После сохранения генерирует событие 'products:changed'.
`getProducts(): IProduct[]` - получение массива всех товаров из модели.
`getProductById(id: string): IProduct | undefined` - получение одного товара по его id.
`setSelectedProduct(product: IProduct): void` -  сохранение товара для подробного отображения. После сохранения генерирует событие 'product:selected'.
`getSelectedProduct(): IProduct | null` - получение товара для подробного отображения.

#### Класс CartModel 
Управляет корзиной покупателя — хранит товары, выбранные для покупки.

Конструктор:
`constructor(events:EventEmitter) { this.events = events;}` - В конструктор передается экземпляр брокера событий EventEmitter, который используется для генерации событий при изменении данных в модели.

Поля класса:
`_items: IProduct[]` - массив товаров, выбранных покупателем для покупки.
`events: EventEmitter` - брокер событий для уведомления об изменениях.

Методы:
`getItems(): IProduct[]` - получение массива товаров, которые находятся в корзине.
`addItem(product: IProduct): void` - добавление товара в массив корзины. Перед добавлением проверяет, нет ли уже такого товара. После добавления генерирует событие 'cart:changed'.
`removeItem(id: string): void` - удаление товара из массива корзины по его id. После удаления генерирует событие 'cart:changed'.
`clear(): void` - полная очистка корзины. После очистки генерирует событие 'cart:changed'.
`getTotalPrice(): number ` - получение стоимости всех товаров в корзине. Суммирует цены всех товаров (товары с ценой null пропускаются).
`getItemCount(): number` - получение количества товаров в корзине.
`containsItem(id: string): boolean` - проверка наличия товара в корзине по его id.

#### Класс OrderModel 
Управляет данными покупателя, которые необходимо указать при оформлении заказа.

Конструктор:
`constructor(events:EventEmitter) { this.events = events;}` - В конструктор передается экземпляр брокера событий EventEmitter, который используется для генерации событий при изменении данных в модели.

Поля класса:
`_payment: TPayment` - вид оплаты (карта, наличные или не выбран).
`_address: string` - адрес доставки.
`_phone: string` - номер телефона.
`_email: string` - email покупателя.
`events: EventEmitter` - брокер событий для уведомления об изменениях.

Методы:
`setOrderData(data: Partial<IBuyer>): void` - охранение данных в модели. Позволяет сохранить как все поля сразу, так и только одно значение (например, только адрес или только телефон), не удаляя при этом значения других полей. После сохранения генерирует событие 'order:changed'.
`getOrderData(): IBuyer` - получение всех данных покупателя.
`clear(): void` - очистка всех данных покупателя (всем полям присваиваются пустые строки). После очистки генерирует событие 'order:changed'.
`validate(field?: keyof IBuyer): Partial<Record<keyof IBuyer, string>>` - валидация данных. Позволяет проверить как все поля сразу (если вызвать без параметра), так и конкретное поле (если передать название поля). Возвращает объект, где ключи — названия полей с ошибками, а значения — текст ошибки. Если поле валидно, оно отсутствует в объекте. Правило валидации: поле является валидным, если оно не пустое.
`isValid(): boolean` - проверяет, валидны ли все данные заказа. Возвращает true, если ошибок нет, и false — если есть хотя бы одна ошибка.

### Слой коммуникации
Отвечает за взаимодействие с сервером — отправку запросов, получение товаров и отправку данных заказа. используются 3 сущности для  типизации данных, которыми приложение обменивается с сервером — получение товаров, отправка заказа и получение подтверждения. Их можно описать такими интерфейсами:

Интерфейс IProductsfromApi описывает структуру ответа сервера при запросе списка товаров. Его поля:
`total:number;` - общее количество товаров в каталоге.
`items: IProduct[];` - массив товаров, где каждый элемент соответствует интерфейсу IProduct.

Интерфейс IOrderData описывает структуру данных, которые отправляются на сервер при оформлении заказа. Он наследуется от интерфейса IBuyer, так как он имеет 4 общих поля, и только два своих уникальных поля Его поля:
`total:number;` - общая сумма заказа.
`items:string[];` - массив идентификаторов товаров, которые покупатель заказывает.

Интерфейс IOrderfromApi описывает структуру ответа сервера после успешного оформления заказа. Его поля:
`id: string;` - уникальный идентификатор оформленного заказа.
`total:number;` - подтверждённая сумма заказа.

#### Класс LarekApi
Отвечает за взаимодействие с сервером API интернет-магазина. Класс использует композицию — внутри себя хранит экземпляр базового класса Api и делегирует ему выполнение HTTP-запросов.

Конструктор:
` constructor(baseUrl: string) { this._api = new Api(baseUrl);}` - Создаёт внутри себя экземпляр класса Api с переданным адресом.

Поля класса:
`_api: Api` -  экземпляр базового класса Api, через который выполняются HTTP-запросы.

Методы:
`getProducts(): Promise<IProductsResponse>` - выполняет GET запрос на эндпоинт /product и возвращает промис с объектом, содержащим массив товаров (поле items) и общее количество (поле total).
`postOrder(orderData: IOrderData): Promise<IOrderResponse>` - выполняет POST запрос на эндпоинт /order, передавая в теле запроса данные о заказе (способ оплаты, контактные данные, адрес, сумму и список id товаров). Возвращает промис с объектом подтверждения, содержащим id заказа и итоговую сумму.

#### Слой View
Компоненты представления отвечают за отображение интерфейса и взаимодействие с пользователем. Они не хранят данные, а только отображают их и генерируют события при действиях пользователя. Все компоненты наследуются от базового класса `Component<T>`. Слой содержит следущие интерфейсы:

Интерфейс ICardData
Описывает базовые данные для отображения в карточке товара. Его поля:
`title: string` - название товара.
`price: number | null` - цена товара. Значение null означает, что товар "Бесценно".
`category?: string` - категория товара (опционально, так как не во всех карточках отображается).
`image?: string` - путь к изображению товара (опционально, так как не во всех карточках отображается).

Интерфейс ICardActions
Описывает действия, которые могут быть переданы в карточку. Его поля:
`onClick?: (event: MouseEvent) => void` - обработчик клика по карточке.

Интерфейс IGallery
Описывает данные для отображения галереи товаров. Его поля:
`catalog: HTMLElement[]` - массив DOM-элементов карточек для отображения в галерее.

Интерфейс IModal
Описывает данные для отображения модального окна. Его поля:
`content: HTMLElement` - DOM-элемент с контентом для отображения внутри модального окна.

Интерфейс IBasket
Описывает данные для отображения корзины. Его поля:
`items: HTMLElement[]` - массив DOM-элементов карточек товаров в корзине.
`total: number` - общая сумма заказа.
`disabled: boolean` - состояние кнопки оформления (активна или заблокирована).

Интерфейс IForm
Описывает базовые данные для формы. Его поля:
`valid: boolean` - состояние валидности формы (все поля заполнены корректно).
`errors: string` - текст ошибки для отображения пользователю.

Интерфейс IOrderForm
Описывает данные формы оплаты и адреса. Наследуется от IForm. Его поля:
`payment: string` - выбранный способ оплаты ('card' или 'cash').
`address: string` - введённый адрес доставки.

Интерфейс IContactsForm
Описывает данные формы контактов. Наследуется от IForm. Его поля:
`email: string` - введённый email покупателя.
`phone: string` - введённый телефон покупателя.

Интерфейс ISuccessForm
Описывает данные для отображения сообщения об успешном заказе. Его поля:
`total: number` - сумма списанных синапсов (итоговая сумма заказа).

#### Класс Header
Отвечает за отображение шапки сайта: логотип, иконка корзины и счётчик товаров в корзине.

Конструктор:
`constructor(protected events: IEvents, container: HTMLElement)` - В конструктор передается экземпляр брокера событий и контейнер с элементом шапки.

Поля класса:
`counterElement: HTMLElement` - элемент с классом `.header__basket-counter`, где отображается количество товаров в корзине.
`basketButton: HTMLButtonElement` - кнопка-иконка корзины для открытия корзины.

Методы:
`set counter(value: number): void` - обновляет текст счётчика. При клике на кнопку корзины генерирует событие basket:open.

#### Класс Gallery
Отвечает за отображение каталога товаров на главной странице.

Конструктор:
`constructor(container: HTMLElement)` - В конструктор передается контейнер с элементом `.gallery`.

Поля класса:
`catalogElement: HTMLElement` - контейнер для карточек товаров.

Методы:
`set catalog(items: HTMLElement[]): void` - очищает контейнер и добавляет переданные карточки товаров.

#### Класс Modal
Управляет модальным окном — открытием, закрытием и отображением контента.

Конструктор:
`constructor(protected events: IEvents, container: HTMLElement)` - В конструктор передается экземпляр брокера событий и контейнер с элементом `.modal`.

Поля класса:
`contentContainer: HTMLElement` - контейнер для динамического контента `(.modal__content)`.
`closeButton: HTMLButtonElement` - кнопка закрытия модального окна `(.modal__close)`.

Методы:
`open(): void` - открывает модальное окно (добавляет класс `modal_active`).
`close(): void` - закрывает модальное окно (удаляет класс `modal_active`).
`set content(value: HTMLElement): void` - очищает контейнер и вставляет новый контент. При клике на крестик генерирует событие `modal:close`.

#### Класс Card (общий родительский класс для всех карточек)
Содержит общую логику для всех карточек: отображение названия, цены, категории и изображения.

Конструктор:
`constructor(container: HTMLElement, protected actions?: ICardActions)` - В конструктор передается контейнер карточки и опциональный объект с действиями.

Поля класса:
`titleElement: HTMLElement` - элемент с названием товара `(.card__title)`.
`priceElement: HTMLElement` - элемент с ценой товара `(.card__price)`.
`categoryElement?: HTMLElement` - элемент с категорией товара `(.card__category)`.
`imageElement?: HTMLImageElement` - элемент с изображением товара `(.card__image)`.
`_id: string` - идентификатор товара.

Методы:
`set title(value: string): void` - устанавливает название товара.
`set price(value: number | null): void` - устанавливает цену. Если цена null, отображается текст "Бесценно".
`set category(value: string): void` - устанавливает категорию и соответствующий CSS-класс для фона.
`set image(value: string): void` - устанавливает изображение, формируя полный URL с помощью CDN_URL.

#### Слой Презентер
Презентер отвечает за связь между слоями Model и View, обрабатывает события и управляет логикой приложения. В данном проекте реализован отдельный класс Presenter, что позволяет избежать высокой связанности компонентов и соответствует принципам ООП.

#### Класс Presenter
Управляет всей логикой приложения: загрузкой товаров, открытием/закрытием модальных окон, добавлением/удалением товаров из корзины, валидацией форм и отправкой заказа на сервер.

Конструктор:
`constructor(catalogModel: CatalogModel, cartModel: CartModel, orderModel: OrderModel, api: LarekApi, events: EventEmitter)` - В конструктор передаются экземпляры моделей данных, коммуникационного слоя и брокера событий.

Поля класса:
`catalogModel: CatalogModel` - модель управления каталогом товаров.
`cartModel: CartModel` - модель управления корзиной.
`orderModel: OrderModel` - модель управления данными заказа.
`api: LarekApi` - слой коммуникации для взаимодействия с сервером.
`events: EventEmitter` - брокер событий для подписки и генерации событий.
`header: Header` - компонент шапки сайта.
`gallery: Gallery` - компонент галереи товаров.
`modal: Modal` - компонент модального окна.
`basket: Basket` - компонент корзины.
`orderForm: OrderForm` - компонент формы оплаты и адреса.
`contactsForm: ContactsForm` - компонент формы контактов.
`successForm: SuccessForm` - компонент сообщения об успешном заказе.
`currentProductId: string | null` - идентификатор текущего открытого товара.

Методы:

`private initViews(): void` - инициализирует все компоненты представления (View), находит контейнеры в DOM и создаёт экземпляры классов.
`private initEvents(): void` - настраивает подписки на события от моделей данных и компонентов представления. Обрабатывает следующие события:
от моделей: products:changed, cart:changed;
от представлений: card:select, card:add, card:remove, basket:remove, basket:open, order:start, order:submit, contacts:submit, modal:close, success:close.
`private loadProducts(): void` - загружает товары с сервера через LarekApi.getProducts() и сохраняет их в модель каталога.
`private renderCatalog(): void` - создаёт карточки товаров из модели каталога и отображает их в галерее.
`private updateBasket(): void` - обновляет содержимое корзины: отображает список товаров, общую сумму и обновляет счётчик в шапке.
`private openProductCard(id: string): void` - открывает модальное окно с детальной информацией о товаре. Проверяет, находится ли товар в корзине, и устанавливает соответствующий текст кнопки.
`private addToBasket(id: string): void` - добавляет товар в корзину. Если товар имеет цену null — добавление не происходит.
`private removeFromBasket(id: string): void` - удаляет товар из корзины и обновляет интерфейс.
`private openBasket(): void` - открывает модальное окно с содержимым корзины.
`private startOrder(): void` - открывает модальное окно с формой оплаты и адреса (первый шаг оформления заказа).
`private openContactsForm(): void` - открывает модальное окно с формой контактов (второй шаг оформления заказа).
`private submitOrder(): void` - собирает данные заказа из моделей, отправляет их на сервер через LarekApi.postOrder(). При успешном ответе отображает сообщение об успешном заказе.
